## [[科技] eMudhra 中间 CA 遭入侵，暴露弱私钥问题](https://emudhra.we-have-a-problem.com/) ⭐️ 7.0/10

**发生了什么**: 证书颁发机构 eMudhra 的中间 CA 私钥遭到入侵，这些私钥被发现在安全性上极其薄弱——有些短至一个字节（例如私钥就是“4”）。该事件通过 Mozilla 的 bug 报告披露，并在 Hacker News 上引发广泛讨论，暴露出用于生成 ECC 颁发者的密钥生成脚本存在缺陷。

**投资影响**: 该事件突显了证书颁发机构安全实践中的严重弱点，以及整个生态系统中吊销基础设施发展不均衡的现状。尽管 Firefox、Chrome、Apple 和 Microsoft 等主要浏览器拥有快速吊销证书的工具，但许多其他依赖方缺乏此类保护，导致物联网设备和其他系统容易受到拦截攻击。

**关键信息**: 据报道，所有八个受影响的 CA 的私钥都只有一个字节，使得它们极易被猜测。eMudhra 将问题归因于某天用于创建 ECC 颁发者的 KGC 脚本存在缺陷，并提到其常规 KGC 流程存在一个已批准的偏差。

hackernews · galadran · 10月20日 13:58 · [社区讨论](https://news.ycombinator.com/item?id=50166579)

**背景**: 证书颁发机构（CA）颁发数字证书，将公钥与身份绑定，构成互联网信任的基石。中间 CA 是隶属于根 CA 的下级 CA，可以代表根 CA 颁发证书。如果中间 CA 的私钥被泄露，攻击者可以为任何域名颁发欺诈性证书，从而实施中间人攻击。CRL 和 OCSP 等吊销机制用于使此类证书失效，但其有效性在整个生态系统中参差不齐。

**社区讨论**: 评论者对私钥只有一个字节表示震惊和沮丧，有人指出私钥字面上就是“4”。一位 Mozilla 代表强调，得益于 OneCRL，Firefox 用户在几小时内就得到了保护，但批评了生态系统其他部分在吊销机制上缺乏投资。其他人则对易受攻击的物联网设备表示担忧，并质疑这些私钥是被发现暴露在外，还是由于生成逻辑薄弱而容易被猜到。

## [[科技] Cloudflare 的 tsrs 项目用伪 GC 内存模型将 TypeScript 移植到 Rust](https://blog.cloudflare.com/typescript-rust-port/) ⭐️ 7.0/10

**发生了什么**: Cloudflare 的 tsrs 项目使用伪 GC 的 arena 内存模型将 TypeScript 移植到 Rust，相比参考实现 tsc/Go 获得了速度提升，并使得 TypeScript 编译能在仅 WASM 的沙箱中运行。该项目已得到 TypeScript 团队成员的验证，并引发了 150 条实质性评论。

**投资影响**: 这一进展意义重大，因为它展示了一种将垃圾回收语言移植到 Rust 的新颖方法，可能实现更快的 TypeScript 编译，并在 WASM 沙箱等受限环境中得到更广泛的应用。它可能影响在大型代码库中使用 TypeScript 的开发者，并影响未来的编译器设计。

**关键信息**: 该项目对长生命周期对象使用永不释放的 arena 来模拟垃圾回收器，从而克服 Rust 缺乏 GC 的问题。TypeScript 团队成员怀疑，速度提升很大程度上来自特定的优化，而不仅仅是语言选择，这些优化也可能使 TypeScript 7.1 受益。

hackernews · hnisjafx40 · 10月20日 13:18 · [社区讨论](https://news.ycombinator.com/item?id=50165953)

**背景**: TypeScript 是 JavaScript 的静态类型超集，可编译为纯 JavaScript，其参考编译器（tsc）用 TypeScript 编写并在 Node.js 上运行。将其移植到 Rust 具有挑战性，因为 Rust 没有垃圾回收器，而 TypeScript 编译器依赖垃圾回收进行内存管理。Cloudflare 需要一个能在仅 WASM 的沙箱中运行且没有 Go 运行时开销的 TypeScript 编译器，这促成了 tsrs 实验。
